* Iteration 1 - conservative contiguous activity segmentation
** Repository evidence
- =RedactedRecord= is the canonical decrypted activity source. It contains exact record ID, capture time, policy revision, redacted OCR, redacted metadata, and redacted pixels; clustering must not use =RawFrame= or bypass redaction.
- Issue #20 already provides deterministic 64-bit RGB8 difference hashing in =capture.adaptive.perceptual_dhash_rgb8=. Reusing that implementation avoids a second image-similarity definition.
- =EncryptedSemanticIndex= intentionally hides stored embedding vectors behind encrypted snapshot/search APIs. Clustering therefore must not crack the index format or expose vectors; when pairwise semantic continuity is needed it can batch the same redacted text through the configured local =EmbeddingProvider= contract from #22.
- =GenerationProvider= already exposes =GenerationRole.SUMMARIZATION= and provider capabilities/location. Activity summarization can therefore remain downstream of redaction and reject non-local providers for this issue rather than creating a second routing system.
- =SQLiteEncryptedStorage= remains canonical for capture records. Activity/session state is derived data and must be replaceable/rebuildable when source membership or policy revision changes.
- Retrieval #24 already treats storage as canonical and decrypted data as bounded working state. Activity clustering should preserve that ownership rather than turn summaries into a second source of truth.

** External research
- Adams and MacKay, “Bayesian Online Changepoint Detection,” models contiguous sequential regimes by detecting abrupt changes in the generating process and tracking the current run length. Source: https://arxiv.org/abs/0710.3742 and https://lips.cs.princeton.edu/pdfs/adams2007changepoint.pdf
- The current =ruptures= change-point documentation describes temporal segmentation as partitioning an ordered signal; its cosine kernel detects changes in mean direction of embedded vectors. Source: https://centre-borelli.github.io/ruptures-docs/user-guide/detection/kernelcpd/ and https://centre-borelli.github.io/ruptures-docs/user-guide/costs/costcosine/
- =ruptures= PELT can find globally optimized breakpoints with pruning, but it is retrospective and adds a substantial numerical dependency/parameter surface. Source: https://centre-borelli.github.io/ruptures-docs/user-guide/detection/pelt/

The important design change from this research is that “cluster” should not mean unconstrained global clustering. User activity is an ordered stream; non-adjacent records from the same application must never be pulled together merely because their embeddings look alike. The correct v0.1 primitive is contiguous segmentation/change detection with conservative boundaries.

** Evidence-derived design
1. Introduce immutable project-owned activity domain types: =ActivityRecordFeatures=, =ActivityCluster=, =ActivitySummary=, and bounded =ActivityClusteringPolicy=. Public reprs contain IDs/counts/times/control values only, never OCR, metadata values, pixels, prompts, or summary text.
2. Input records are sorted by =(captured_at, record_id)= and segmented only against the immediately preceding accepted record/segment. Clusters are always contiguous in source time; no global/non-contiguous merge pass is permitted.
3. A time gap greater than =max_gap_seconds= is a hard boundary. Workspace change is a hard boundary when both workspaces are known. Missing workspace/application data reduces confidence rather than being guessed.
4. Application change is a strong boundary signal, not an unconditional boundary: a short editor↔browser hop may remain one activity only when semantic continuity is strong and the time gap is small. Same application never guarantees continuity; repeated use of Emacs/Firefox for different tasks must still split when semantic/perceptual evidence is weak.
5. Perceptual continuity reuses =perceptual_dhash_rgb8= on the already-redacted frame and normalized Hamming similarity =1 - changed_bits/64=. It is supporting evidence only; visually static but semantically different text must not force a merge.
6. Semantic continuity is cosine similarity between local embedding vectors created from bounded redacted OCR plus approved application/workspace metadata. Pairwise vectors are produced in one bounded batch; no remote provider is eligible for clustering.
7. Continuity is conservative and deterministic. Hard boundaries win first. Otherwise same-application, perceptual, semantic, and short-gap evidence form a bounded score. A merge occurs only when score >= configured threshold and every required evidence item is available. Ambiguous/low-confidence pairs split.
8. Exact source membership is stored as an ordered tuple of record IDs. Cluster start/end are first/last source timestamps; a repeated-frame run therefore becomes one activity span without manufacturing intermediate captures.
9. Summary generation is local-only and incremental. The generation prompt contains only bounded redacted text plus opaque source labels. The model must return a strict JSON claim envelope. Each claim must cite one or more cluster source IDs and include an evidence excerpt that exactly occurs in the corresponding redacted source text. Invalid JSON, foreign IDs, missing citations, or non-matching excerpts reject the generated summary. Stored summaries omit the excerpts but retain the exact source IDs for every accepted claim.
10. Model output cannot become canonical evidence. =ActivitySummary= is explicitly derived/model-generated, records provider/model ID and source membership, and can always be regenerated. Query answering later must retain record citations rather than cite a summary alone.
11. Persist derived clusters/summaries in a dedicated owner-only encrypted activity snapshot using the existing =KeyProvider= envelope pattern, not plaintext SQLite columns. The encrypted snapshot stores cluster membership, summary text, provider/model provenance, policy revision set, and a deterministic source fingerprint.
12. Reconciliation is full replacement from canonical records in v0.1. Deletion removes source IDs naturally; changed redaction/policy revision changes the fingerprint and forces affected summary regeneration. This is intentionally simpler and safer than in-place partial graph mutation. The write remains atomic and resumable by rebuilding from source records.
13. Provider unavailability does not block clustering. Clusters may exist with =summary=None= and can be summarized later. Cancellation/failure never publishes a partially generated replacement snapshot.

** Rejected alternatives
- DBSCAN/HDBSCAN/k-means over all embeddings: ignores chronology and can merge unrelated non-adjacent tasks that happen to use the same application/topic;
- importing =ruptures= for v0.1: useful research reference but unnecessary dependency/parameter surface for a deterministic online-compatible boundary policy with explicit acceptance fixtures;
- reading private embedding vectors from =EncryptedSemanticIndex=: breaks the index abstraction and couples clustering to encrypted snapshot internals;
- application equality as the primary grouping key: fails the explicit repeated-same-application/different-task case;
- perceptual hash equality as the primary grouping key: static UIs can show semantically different content, and tiny layout changes can obscure a coherent task;
- model-generated cluster boundaries: non-deterministic, expensive, hard to regression-test, and violates the requirement for exact reproducible membership;
- storing summaries or cluster labels in plaintext SQLite metadata: expands the plaintext leakage budget;
- accepting free-form model summaries solely because the prompt says “do not hallucinate”: prompts are not an enforceable evidence boundary;
- claiming exact semantic truth from embedding cosine: similarity is only a heuristic signal and cannot authorize a merge by itself when stronger hard-boundary evidence disagrees.

** Security/privacy invariants
- clustering consumes =RedactedRecord= only; raw/unredacted frames are structurally outside the API;
- no remote provider is used for embedding or summarization in this issue;
- source membership is exact and ordered; no summary can cite a record outside its cluster;
- no model output can add source membership;
- summary evidence excerpts must match already-redacted source text and are not persisted in the derived snapshot;
- low-confidence/ambiguous continuity splits rather than merges;
- derived activity state is rebuildable and never overrides canonical capture records;
- plaintext filesystem/catalog surfaces do not gain OCR, summary, application/workspace values, embeddings, or pixel data;
- cancellation/provider failure cannot publish a partial replacement;
- repr/errors/status remain content-free.

** Failure/race analysis
- record deleted between retrieval and reconciliation -> the next reconciliation omits it; derived state is replace-only and cannot resurrect it;
- record policy revision changes -> source fingerprint changes and dependent summary is regenerated;
- embedding provider returns wrong count/dimensions/non-finite values -> fail the semantic clustering batch rather than silently downgrading merge confidence;
- local generation provider unavailable -> preserve deterministic clusters without summaries and retry later;
- model cites unknown source ID or fabricated excerpt -> reject that summary, preserve the prior valid snapshot if one exists;
- cancellation during embedding/generation/encryption/write -> propagate cancellation and leave previous snapshot authoritative;
- equal timestamps -> stable record-ID ordering makes membership deterministic;
- application/workspace metadata absent -> confidence decreases; never invent values;
- very long input window -> explicit record/context/token limits bound embedding and generation batches;
- policy/context boundary changes inside adjacent records -> different redaction policy revisions are a hard cluster boundary so summaries never mix authorization/redaction epochs implicitly.
