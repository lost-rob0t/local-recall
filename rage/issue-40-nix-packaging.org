* Acceptance criteria
- =nix flake check= passes.
- A clean NixOS test VM can install, start, control, capture synthetic Xorg content, stop, and query.
- Service sandboxing does not grant unnecessary home-directory or network access.
- Uninstalling preserves or removes encrypted user data only according to an explicit choice.

* Issue status
- OPEN by design. The packaging, hardening, completions, VM test, and uninstall
  semantics are implemented and verified (=nix flake check= green, VM test 15
  assertions green under KVM).
- Criterion 2 requires the long-running daemon process ("start, control,
  capture, stop, query"). No prior issue built a =local-recall daemon= command:
  every command in the closed CLI set is a client of the authenticated IPC
  boundary, and the server process hosting the actor/IPC loop is the pending
  release-gate item. Adding a stub daemon command to make the VM test look
  complete would be exactly the false-green the repo policy forbids, so the VM
  test instead verifies clean install, CLI fail-closed behavior (exit 3 +
  sanitized =daemon-unavailable=), unit hardening, state-directory ownership,
  config generation, and the non-enabled destroy unit. The remaining human
  blocker is the daemon process implementation.

* Design decisions
- Package: =buildPythonPackage= on =python314Packages= (pydantic, pykka, pynacl,
  pyzmq, typer from nixpkgs), hatchling build, =pythonImportsCheck=, and
  bash/zsh/fish completions generated in =postInstall= from the installed CLI
  itself (typer =--show-completion=).
- Overlay: =overlays.default= exposes =local-recall= via =callPackage= so the
  module and other configurations share one definition (=nix/package.nix=).
- Module (=nix/module.nix=): dedicated system user with linger owning
  =/var/lib/local-recall=; generated TOML config at
  =/etc/local-recall/config.toml=; hardened systemd =user= unit. =startMode=
  defaults to ="off"= and writes =capture.enabled=false=. =networkAllowLoopback=
  defaults to false (=IPAddressDeny=any=) with an explicit loopback opt-in for
  the IPC endpoint and local providers.
- Hardening set: NoNewPrivileges, PrivateTmp/PrivateDevices, ProtectClock/
  Hostname/KernelLogs/KernelModules/KernelTunables/ControlGroups,
  ProtectProc=invisible, RestrictSUIDSGID/Realtime/Namespaces, LockPersonality,
  RemoveIPC, UMask=0077, empty CapabilityBoundingSet, SystemCallFilter
  @system-service minus privileged/obsolete/resources/mount,
  SystemCallArchitectures=native, ProtectHome=read-only (no home writes;
  state dir is the only ReadWritePaths entry).
- Uninstall: removing the module preserves the encrypted state directory. Data
  destruction exists only as the =local-recall-destroy-data= oneshot with
  =wantedBy = []= — it can never trigger implicitly.
- VM test (=nix/vm-test.nix=): boots a clean NixOS VM under KVM, asserts
  =local-recall version=, fail-closed =status= (exit 3 + sanitized reason),
  every hardening directive in the rendered unit, state-directory ownership,
  generated config content (=enabled = false=), and that the destroy unit is
  wanted by nothing.
