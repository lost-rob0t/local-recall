* Acceptance criteria
1. Another local user cannot control or query the daemon.
2. Socket permissions and peer identity are validated at startup and per connection where supported.
3. Fuzzed malformed requests cannot crash the daemon or leak captured/private content.
4. CLI and recording-status indicator use the authenticated local API rather than direct daemon-internal imports.

* Issue requirements
- Prefer a Unix-domain socket with owner-only permissions on Linux.
- Authenticate clients and authorize control, query, export, and deletion operations separately where useful.
- Bind no TCP listener by default.
- Bound request size, concurrency, and deadlines/timeouts.
- Prioritize stop/privacy requests over query/model work.
- Sanitize all errors and audit security-relevant requests.
- Keep a transport abstraction so a loopback transport may be added deliberately later.

* Hard project invariants carried into this issue
- Local-first; no silent remote fallback.
- IPC must not bypass lifecycle, policy, privacy-mode, lock-state, retrieval, redaction, provider-egress, storage, or audit authorities.
- Content-bearing request/response data must not enter sanitized status, errors, or audit records.
- No plaintext screenshot/OCR/decrypted-working-set persistence is introduced by IPC.
- Stop/privacy controls must fail closed and must not be starved behind ordinary query/model work.
- No TCP listener is introduced by default.

* RAGE iteration 1
** Research
- Linux =unix(7)=: pathname AF_UNIX sockets are filesystem objects; directory permissions and socket mode constrain connection, but portable software must not treat pathname permissions as the sole authentication mechanism. Linux exposes kernel-derived connected-peer credentials through =SO_PEERCRED=.
- XDG Base Directory 0.8: =$XDG_RUNTIME_DIR= is specifically intended for per-user runtime objects including sockets, must be owner-owned, local, mode 0700, and lifetime-bound to the login session. This is the preferred parent directory; invalid/missing runtime directories must fail closed rather than fall back to a shared =/tmp= pathname.
- Current libzmq/PyZMQ expose =IPC_FILTER_UID= for IPC listeners backed by peer credentials. The libzmq option is deprecated in favor of ZAP/IPC allow-block mechanisms, so it is acceptable only as Linux defense in depth, not the long-term protocol authentication authority.
- Existing architecture already commits v0.1 CLI/query IPC to ZeroMQ =ROUTER/DEALER= over =ipc://= with bounded HWM/timeouts/linger and an authenticated session token. Replacing this with a second raw-socket protocol would create competing transport semantics and violate the architecture.
- Existing threat model TB-06 requires owner-only Unix socket placement, safe directory, peer identity, request limits, and capability separation; same-UID malicious processes are explicitly outside the strong isolation guarantee, so the goal is to exclude other UIDs and keep command capabilities explicit rather than claiming same-UID secrecy.

** Evidence-derived design
- Keep ZeroMQ =ipc://= as the transport and add a project-owned authenticated IPC layer beneath the existing =DaemonClient= port.
- Endpoint resolution: only an absolute validated =$XDG_RUNTIME_DIR=/local-recall/control.sock= style path under an owner-owned 0700 runtime directory. Reject symlink/non-directory/wrong-owner/wrong-mode parents. Never bind TCP or abstract Unix sockets in v0.1.
- Listener hardening: explicit ROUTER socket options, finite HWM/send/receive timeouts, =LINGER= 0, and Linux UID filtering when supported. After bind, verify the socket node is a socket, owned by the daemon UID, and mode 0600; cleanup only the exact validated socket node owned by the daemon.
- Protocol authentication: issue an owner-only random session token in the runtime directory, mode 0600, generated at daemon startup and rotated on restart. Requests carry token material in a dedicated non-logged frame; routing JSON stays content-free. Token comparison is constant-time. Filesystem/UID controls are defense in depth; the token is the protocol authentication authority.
- Authorization: map the closed =CliCommand= set to capabilities: lifecycle/control, query, diagnostics; future export/delete capabilities remain distinct. A client session is authorized per command, never by arbitrary method strings.
- Framing: versioned multipart message with bounded routing frame, authentication frame, and bounded content frame. No pickle or arbitrary Python objects. Unknown frame count, oversized frames, malformed UTF-8/JSON, protocol mismatch, priority mismatch, expired deadline, or invalid command fail with fixed sanitized reason codes.
- Scheduling: urgent stop/privacy requests enter a dedicated bounded urgent lane serviced before ordinary control/query lanes; no unbounded retry or hidden queue. Query concurrency is separately bounded.
- Audit: accepted/rejected authentication, authorization, overload, timeout, malformed request, and completion produce fixed event/reason/capability metadata only. Request text, response text, token bytes, endpoint paths, usernames, titles, and provider payloads are forbidden from audit events.
- CLI/indicator: default CLI client factory becomes the authenticated IPC client. Indicator presentation remains transport-agnostic and consumes only the shared =DaemonClient= boundary; it imports no lifecycle/capture/storage/provider internals. Packaging/runtime composition may inject the same authenticated client without creating a second daemon authority.

*** Rejected alternatives
1. Raw =asyncio.start_unix_server= protocol beside ZeroMQ: rejected as a second transport stack conflicting with ADR-0006/architecture.
2. Socket chmod only: rejected because Linux pathname permissions are defense in depth and do not provide protocol authentication.
3. =IPC_FILTER_UID= as sole auth: rejected because libzmq deprecates the filter and same-UID identity is too coarse for explicit protocol/session authentication.
4. CURVE keypairs for local v0.1 IPC: rejected for the first slice as unnecessary key-distribution complexity; owner runtime-dir token + peer UID/permissions satisfies the stated local-user threat while preserving a future ZAP/CURVE upgrade path.
5. TCP loopback fallback: rejected; issue and architecture require no default TCP listener.

*** Failure/race analysis
- Stale socket node at startup: remove only after lstat verifies a same-owner socket node under the validated runtime directory; regular file/symlink/wrong-owner is a startup fault.
- Runtime directory replaced between validation and bind: revalidate parent identity/ownership immediately around bind and verify bound node after creation; treat mismatch as fault and tear down.
- Token file replacement/permission drift: server owns creation; clients require regular non-symlink file, same UID, mode 0600, bounded exact token length.
- Client disconnect/cancel: finite deadlines and zero linger; no successful result may be synthesized after timeout/cancellation.
- Query saturation cannot starve STOP/privacy: separate urgent bounded lane and explicit priority validation.
- Executor queue delay may consume the remaining request deadline. Therefore a request is rechecked immediately before handler entry and again after handler return; expired queued work never enters the handler and a late handler result cannot be reported as success.
