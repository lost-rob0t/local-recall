* Iteration 1 - claim-level cited answering over canonical retrieval
** Repository evidence
- =RetrievalService= is already the authoritative bounded decrypt-and-filter path. =RetrievalQuery= carries a resolved timezone-aware range, application/workspace filters, normalized keywords, optional semantic text, metadata filters, result/candidate bounds, and a query UUID. =RetrievalBatch= preserves the retrieval policy revision and a conservative =remote_provider_eligible= bit after query and per-record policy checks.
- =RetrievedPassage= already exposes exactly the evidence needed for citation validation: canonical =record_id=, =captured_at=, bounded redacted =excerpt=, retrieval score, metadata provenance, redaction policy revision, and finding count. QA must not reopen storage/decryption independently.
- #25 =ActivityCluster= preserves exact ordered source-record membership and start/end timestamps. =ActivitySummary= is derived/model-generated and intentionally not canonical evidence. The #25 RAGE design explicitly requires later QA to retain record citations rather than cite summaries alone.
- =ActivitySummarizer= established a strong precedent: structured model output is parsed and validated against exact source IDs and verbatim evidence before becoming accepted derived state. QA should reuse that trust model rather than accept free-form generated citations.
- =RoutingPolicy= already enforces the four routing modes. =local-first= is deliberately local-only on local failure; it does not fall through to remote. =remote-explicit= requires a concrete =EgressAuthorization= bound to provider and data classes.
- =EgressGate= rescans outgoing redacted text/metadata for deterministic secrets, checks authorization data classes and payload bounds, and returns an immutable approved payload. QA must use this gate for any remote generation instead of passing =RetrievedPassage.excerpt= directly to a remote provider.
- Query execution has no reason to import capture/lifecycle actors. The QA service should depend on retrieval, activity-index lookup, provider routing, and generation ports only.

** External research
- Gao et al., “Enabling Large Language Models to Generate Text with Citations” (ALCE, arXiv:2305.14627) evaluates citation correctness and completeness separately and reports that even strong systems frequently lack complete citation support. This argues for validating support per generated claim rather than treating the presence of some citations as sufficient. Source: https://arxiv.org/abs/2305.14627
- Ru et al., “RAGCHECKER: A Fine-grained Framework for Diagnosing Retrieval-Augmented Generation” (arXiv:2408.08067) uses claim-level entailment/evidence checks to diagnose retrieval and generation separately. The actionable design lesson here is stage separation: retrieval evidence quality and answer-claim support are distinct gates. Source: https://arxiv.org/abs/2408.08067

The design change from this evidence is that the model will not generate final Markdown with ad-hoc citation syntax. It returns a closed JSON claim envelope referencing opaque evidence IDs supplied by Local Recall. Local Recall validates every factual claim against the retrieved working set and then renders citations itself. This makes citation syntax and source membership deterministic and prevents the model from inventing record IDs/timestamps.

** Evidence-derived design
1. Add a dedicated =local_recall.answering= boundary rather than embedding QA behavior in retrieval or CLI. Retrieval remains evidence selection; answering remains evidence-constrained generation/rendering.
2. Define immutable project-owned types: =AnswerMode= (=concise=, =timeline=), =AnswerClaimKind= (=observed=, =inference=), =AnswerCitation=, =AnswerClaim=, =CitedAnswer=, =AnswerRequest=, and sanitized =AnswerFailure= reason codes. Public reprs report IDs/counts/control state only and redact question/claim text.
3. Query planning is deterministic first, model-free for the supported v0.1 grammar. Reuse #24's time resolver for explicit/relative time phrases. Parse only bounded recognized selectors (application/workspace phrases plus remaining concept text). Ambiguous unsupported selectors remain concept text or produce an explicit planning failure; never let an LLM silently widen the time range.
4. The planner emits one canonical =RetrievalQuery=. Question/concept text may feed =semantic_text=, while explicitly recognized application/workspace selectors feed typed filters. Retrieval bounds are fixed by answering policy, not model output.
5. Build an immutable evidence table from =RetrievalBatch.passages=. Each passage receives a short opaque evidence label local to this request (for example =E1=) mapped internally to the canonical record ID and capture timestamp. The model sees bounded redacted excerpts plus opaque labels, not arbitrary storage identifiers supplied as writable output fields.
6. If retrieval returns no passages, or if all passages fall below the configured minimum retrieval score, return =insufficient-evidence= without invoking a generation provider.
7. Select the generation provider through existing =RoutingPolicy= and provider capabilities. For a local decision, call the selected local provider directly with =PrivacyClass.REDACTED_CONTENT=. For remote-explicit, require =RetrievalBatch.remote_provider_eligible=, route with the caller's explicit authorization, serialize only the bounded redacted evidence/question payload, pass it through =EgressGate=, and provide only the approved payload to the remote adapter. No other route may contact remote providers.
8. Require structured generation output with exactly one top-level =claims= array. Each claim has exactly =kind=, =text=, and =evidence_ids=. =kind= is =observed= or =inference=. =evidence_ids= must be a non-empty unique subset of the supplied evidence labels. Unknown IDs, duplicate IDs, empty citations, unknown fields/kinds, oversized text, excessive claims, invalid JSON, or provider identity mismatch reject the generated answer.
9. =observed= claims must be directly supportable from cited retrieved excerpts. For v0.1, enforce support structurally by requiring the claim text to be composed only from normalized exact substrings/sentences present in the cited excerpts, or by using an evidence-excerpt form analogous to #25. Do not rely on a second model to judge entailment.
10. =inference= claims may paraphrase/synthesize but remain visibly marked as inference and must cite all source records used. The output renderer must never present inference with the same marker as observed evidence.
11. “Unavailable information” is generated by Local Recall, not the model. If evidence cannot support a requested fact, return an explicit unavailable/insufficient-evidence section rather than allowing the model to manufacture a negative factual claim.
12. =CitedAnswer= stores the resolved query range, answer mode, retrieval policy revision, route/provider class, and validated claims/citations in memory only. It does not persist question or generated answer text as part of issue #26.
13. Rendering is deterministic. Concise mode emits validated claims in score/time-aware order with inline record/timestamp citations. Timeline mode sorts cited evidence chronologically and groups validated claims by source cluster/time span. Citation text is created from =AnswerCitation=, never copied from model output.
14. Activity-cluster linkage is derived by matching each cited record ID against the current activity snapshot/index. A citation may include a cluster ID/span only when exact membership is known; record ID + timestamp remains canonical fallback. A deleted/stale cluster cannot invalidate the underlying record citation.
15. Cancellation, timeout, route/provider failure, malformed model output, stale retrieval-policy revision, or evidence-membership mismatch yields no partially accepted answer. Sanitized failures carry fixed reason codes only.

** Rejected alternatives
- free-form Markdown answer with model-authored =[record-id]= citations: permits hallucinated IDs/timestamps and makes citation parsing part of the trust boundary;
- asking the model to decide which records are trustworthy after retrieval: duplicates retrieval-policy authority and allows generation to widen/narrow policy-selected evidence opaquely;
- citing =ActivitySummary= as canonical evidence: summaries are model-derived and #25 explicitly keeps canonical membership in source records;
- second-LLM factuality grading: adds another non-deterministic authority and may accept mutually reinforcing hallucinations;
- exposing raw UUIDs as arbitrary model output values: unnecessary; short per-request evidence labels reduce prompt size and are easier to validate strictly;
- permitting local-first to remote-fallback when Ollama/local generation fails: contradicts #23 routing semantics and privacy guarantees;
- planning time ranges entirely with an LLM: relative-date resolution is security/retrieval scope and must remain deterministic under the configured timezone;
- persisting answer/question history in #26: expands sensitive retained state without an issue requirement and complicates deletion/retention semantics owned by later issues.

** Security/privacy invariants
- query answering consumes only already-redacted/decrypted bounded working sets from canonical =RetrievalService=; it does not call raw storage/decryption directly;
- local-only/privacy-strict/local-first routes make zero remote requests, including on local provider failure;
- remote generation receives only explicitly authorized already-redacted payloads through existing =RoutingPolicy= + =EgressGate=;
- every accepted factual claim has one or more citations mapped to canonical retrieved record IDs/timestamps; model output cannot add source membership;
- observed and inferred claims are typed and rendered differently; unavailable information is a Local Recall control outcome, not model prose;
- empty/weak retrieval fails closed before generation;
- raw pixels, unredacted metadata, decrypted record objects, prompts, provider payloads, questions, and generated answers do not enter sanitized logs/status/errors;
- cancellation/timeouts/provider failures/malformed output cannot publish partial answers as complete;
- QA imports no capture/lifecycle control surface and cannot start/resume capture.

** Failure/race analysis
- source deleted after retrieval but before rendering -> revalidate citation membership through a narrow evidence-validity callback or final retrieval snapshot token; if any source is no longer valid, reject/retrieve again rather than cite stale evidence;
- retrieval policy revision changes during generation -> final policy revision recheck invalidates the generated answer;
- activity snapshot is stale/deleted -> omit cluster annotation but retain canonical record citation only if record remains valid;
- provider returns unknown evidence labels/duplicate labels/empty citations -> reject whole generation;
- provider returns valid IDs but unsupported observed text -> reject whole generation rather than downgrade it silently;
- provider unavailable under local-only/local-first/privacy-strict -> sanitized =provider-unavailable=; never try remote;
- explicit remote authorization does not cover all selected evidence/data classes -> fail before network call;
- question or evidence exceeds provider/input bounds -> deterministic bounded planning/truncation at evidence boundaries or fail =input-too-large=; never truncate inside a citation in a way that changes its evidence mapping;
- cancellation during retrieval/routing/generation -> propagate cancellation; no partial answer object;
- equal capture timestamps -> stable =(captured_at, record_id)= ordering;
- weak retrieval scores -> explicit insufficient evidence, even if a model could produce plausible prose.
