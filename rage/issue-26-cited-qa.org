* Iteration 1 - claim-level cited answering over canonical retrieval
** Repository evidence
- =RetrievalService= is already the authoritative bounded decrypt-and-filter path. =RetrievalQuery= carries a resolved timezone-aware range, application/workspace filters, normalized keywords, optional semantic text, metadata filters, result/candidate bounds, and a query UUID. =RetrievalBatch= preserves the retrieval policy revision and a conservative =remote_provider_eligible= bit after query and per-record policy checks.
- =RetrievedPassage= already exposes exactly the evidence needed for citation validation: canonical =record_id=, =captured_at=, bounded redacted =excerpt=, retrieval score, metadata provenance, redaction policy revision, and finding count. QA must not reopen storage/decryption independently.
- #25 =ActivityCluster= preserves exact ordered source-record membership and start/end timestamps. =ActivitySummary= is derived/model-generated and intentionally not canonical evidence. The #25 RAGE design explicitly requires later QA to retain record citations rather than cite summaries alone.
- =ActivitySummarizer= established a strong precedent: structured model output is parsed and validated against exact source IDs and verbatim evidence before becoming accepted derived state. QA should reuse that trust model rather than accept free-form generated citations.
- =RoutingPolicy= already enforces the four routing modes. =local-first= is deliberately local-only on local failure; it does not fall through to remote. =remote-explicit= requires a concrete =EgressAuthorization= bound to provider and data classes.
- =EgressGate= rescans outgoing redacted text/metadata for deterministic secrets, checks authorization data classes and payload bounds, and returns an immutable approved payload. QA must use this gate for any remote generation instead of passing =RetrievedPassage.excerpt= directly to a remote provider.
- Query execution has no reason to import capture/lifecycle actors. The QA service should depend on retrieval, activity-index lookup, provider routing, and generation ports only.

** External research
- Gao et al., “Enabling Large Language Models to Generate Text with Citations” (ALCE, arXiv:2305.14627) evaluates citation correctness and completeness separately and reports that even strong systems frequently lack complete citation support. This argues for validating support per generated claim rather than treating the presence of some citations as sufficient. Source: https://arxiv.org/abs/2305.14627
- Ru et al., “RAGCHECKER: A Fine-grained Framework for Diagnosing Retrieval-Augmented Generation” (arXiv:2408.08067) uses claim-level entailment/evidence checks to diagnose retrieval and generation separately. The actionable design lesson here is stage separation: retrieval evidence quality and answer-claim support are distinct gates. Source: https://arxiv.org/abs/2408.08067

The design change from this evidence is that the model will not generate final Markdown with ad-hoc citation syntax. It returns a closed JSON claim envelope referencing opaque evidence IDs supplied by Local Recall. Local Recall validates every factual claim against the retrieved working set and then renders citations itself. This makes citation syntax and source membership deterministic and prevents the model from inventing record IDs/timestamps.

** Evidence-derived design
1. Add a dedicated =local_recall.answering= boundary rather than embedding QA behavior in retrieval or CLI. Retrieval remains evidence selection; answering remains evidence-constrained generation/rendering.
2. Define immutable project-owned types: =AnswerMode= (=concise=, =timeline=), =AnswerClaimKind= (=observed=, =inference=), =AnswerCitation=, =AnswerClaim=, and =CitedAnswer=. Public reprs report IDs/counts/control state only and redact question/claim text.
3. Query planning is deterministic first, model-free for the supported v0.1 grammar. Reuse #24's time resolver for explicit/relative time phrases. Parse only bounded recognized selectors (application/workspace phrases plus remaining concept text). Ambiguous unsupported selectors remain concept text or produce an explicit planning failure; never let an LLM silently widen the time range.
4. The planner emits one canonical =RetrievalQuery=. Question/concept text may feed =semantic_text=, while explicitly recognized application/workspace selectors feed typed filters. Retrieval bounds are fixed by answering policy, not model output.
5. Build an immutable evidence table from =RetrievalBatch.passages=. Each passage receives a short opaque evidence label local to this request (for example =E1=) mapped internally to the canonical record ID and capture timestamp. The model sees bounded redacted excerpts plus opaque labels, not canonical storage identifiers.
6. If retrieval returns no passages, or if all passages fall below the configured minimum retrieval score, return =insufficient-evidence= without invoking a generation provider.
7. Select the generation provider through existing =RoutingPolicy= and provider capabilities. For a local decision, call the selected local provider directly with =PrivacyClass.REDACTED_CONTENT=. For remote-explicit, require =RetrievalBatch.remote_provider_eligible=, route with the caller's explicit authorization, serialize only the bounded redacted evidence/question payload, pass it through =EgressGate=, and provide only the approved payload to the remote adapter. No other route may contact remote providers.
8. Require structured generation output with exactly one top-level =claims= array. Each claim has exactly =kind=, =text=, and =evidence_ids=. =kind= is =observed= or =inference=. =evidence_ids= must be a non-empty unique subset of the supplied evidence labels. Unknown IDs, duplicate IDs, empty citations, unknown fields/kinds, oversized text, excessive claims, invalid JSON, or provider identity mismatch reject the generated answer.
9. =observed= claims must be directly supportable from cited retrieved excerpts. For v0.1, enforce support structurally by requiring the normalized observed text to occur in the cited excerpts. Do not rely on a second model to judge entailment.
10. =inference= claims may paraphrase/synthesize but remain visibly marked as inference and must cite all source records used. The output renderer must never present inference with the same marker as observed evidence.
11. “Unavailable information” is generated by Local Recall, not the model. If evidence cannot support a requested fact, return an explicit unavailable/insufficient-evidence result rather than allowing the model to manufacture a negative factual claim.
12. Answer objects remain in memory in issue #26. Persisting question/answer history belongs to later explicit retention/product work.
13. Rendering is deterministic. Concise mode emits validated claims with inline record/timestamp citations. Timeline mode sorts by canonical capture time. Citation text is created from =AnswerCitation=, never copied from model output.
14. Activity-cluster linkage is derived by matching each cited record ID against the supplied activity snapshot. A citation includes an activity span only when exact membership is unambiguous; record ID + timestamp is the canonical fallback.
15. Cancellation, route/provider failure, malformed model output, or evidence-membership mismatch yields no partially accepted answer. Sanitized failures carry fixed/control-only text.

** Rejected alternatives
- free-form Markdown answer with model-authored record citations: permits hallucinated IDs/timestamps and makes citation parsing part of the trust boundary;
- asking the model to decide which records are trustworthy after retrieval: duplicates retrieval-policy authority;
- citing =ActivitySummary= as canonical evidence: summaries are model-derived;
- second-LLM factuality grading: adds another non-deterministic authority;
- exposing raw UUIDs as writable model output values: unnecessary and larger;
- permitting local-first to remote-fallback when local generation fails: contradicts #23 routing semantics;
- planning time ranges entirely with an LLM: relative-date resolution is retrieval scope and stays deterministic;
- persisting answer/question history in #26: expands sensitive retained state without an issue requirement.

** Security/privacy invariants
- query answering consumes only bounded =RetrievalService= results; it does not call raw storage/decryption directly;
- local-only/privacy-strict/local-first make zero remote requests, including on local provider failure;
- remote generation receives only explicitly authorized redacted text through =RoutingPolicy= + =EgressGate=;
- every accepted claim has canonical retrieved record/timestamp citations; model output cannot add source membership;
- observed and inferred claims are typed and rendered differently;
- empty/weak retrieval fails closed before generation;
- raw pixels, unredacted metadata, decrypted record objects, prompts, provider payloads, questions, and generated answers do not enter sanitized repr/status/error surfaces;
- QA imports no capture/lifecycle/storage/remote-transport control surface and cannot start/resume capture.

** Failure/race analysis
- source/activity cluster missing at render time -> omit activity annotation and retain canonical record/timestamp citation from the retrieval snapshot; deletion consistency is owned by the later deletion issue;
- provider returns unknown evidence labels/duplicates/empty citations -> reject whole generation;
- provider returns valid labels but unsupported observed text -> reject whole generation rather than silently downgrade;
- provider unavailable under local-only/local-first/privacy-strict -> propagate failure; never try remote;
- explicit remote authorization or retrieval eligibility missing -> fail before remote invocation;
- question/evidence exceeds provider/input bounds -> fail before provider invocation; never truncate inside a citation mapping;
- cancellation during retrieval/routing/generation -> propagate cancellation; no partial answer object;
- equal capture timestamps -> stable canonical order;
- weak retrieval scores -> explicit insufficient evidence even if plausible prose could be generated.
