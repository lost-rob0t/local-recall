* Iteration 2 - XWD stdout capture with process isolation
:PROPERTIES:
:SUPERSEDES: Iteration 1 native Xlib acquisition choice
:END:

** Why the architecture changed
Further adversarial research disproved the initial assumption that in-process Xlib was the strongest bounded implementation. X.Org =xwd= can emit a root-window dump to stdout without a file. Its XWD header is a small specified structure with version, dimensions, byte order, bits-per-pixel, stride, visual class, masks, color-table count and root geometry. A fixed helper process can be killed on timeout/cancellation, providing a stronger isolation boundary than a blocking FFI call.

The earlier blanket rejection of =xwd= was therefore wrong. The real hazards are shell/file behavior, uncontrolled executable identity, hostile output and permissive decoding. Those are addressed directly by fixed absolute executables, no shell, stdout-only capture, strict parsing, output caps, minimal environment and child termination.

** Final acquisition design
1. =XorgCaptureBackend= remains the only public Xorg pixel adapter and accepts only =ApprovedCaptureRequest=.
2. =XwdSnapshotReader= reads monitor topology, obtains one root XWD byte stream, re-reads topology, rejects changes, strictly validates the XWD payload and emits canonical packed RGB8.
3. =FixedXwdNativeRunner= exposes only =xwd -root -silent= and =xrandr --listmonitors=.
4. =BoundedNativeCommandExecutor= maps those fixed command IDs to supplied absolute paths, uses no shell, passes only minimum X11/session environment plus fixed C locale, bounds stdout/stderr, derives timeout from the immutable request deadline, and terminates a live child on timeout, overflow or caller cancellation.
5. Monitor/root/crop geometry and scale are retained as typed capture provenance.
6. Focused-window mode remains a trusted in-memory crop from the single root capture.
7. Public errors contain fixed reason codes only; native output, executable paths, display values, pixels and private metadata are excluded.

** Failure and race analysis
- missing/disconnected X display or nonzero =xwd= -> sanitized failure; no frame;
- malformed/truncated/oversized/unsupported XWD -> =capture-format-invalid= before =RawFrame=;
- monitor topology changes around capture -> =display-changed=; no frame;
- expired request -> fail before helper spawn;
- deadline during helper -> terminate child and fail boundedly;
- caller cancellation -> terminate child, clean stream tasks, propagate cancellation;
- live stdout/stderr overflow -> terminate child and return fixed failure;
- hostile =LD_PRELOAD=/proxy/unrelated environment -> not passed to helpers;
- untrusted/malformed/out-of-root focused geometry -> do not perform arbitrary crop/drawable capture;
- lock/privacy/stop/fault generation changes after acquisition -> producer generation must remain attached through ingress and stale work must be rejected.

** Defect discovered during issue-level integration
The first end-to-end Xorg/pipeline acceptance trace exposed a real stale-work gap outside the backend itself. =BoundedCapturePipeline.submit_raw()= acquired whatever generation was current at submission time and constructed =RawStageItem= with that permit generation. A frame captured under generation N could therefore be submitted after lock/privacy invalidation and resume to generation N+1 and be relabelled N+1 instead of being rejected as stale.

That violates #19's requirement that a late native/captured result never become accepted downstream work after authorization invalidation. Fixing only the Xorg caller would leave the unsafe public raw-ingress API available to every future capture backend, so the smallest coherent security boundary is the pipeline submission API itself.

** Revised invariant
Every raw producer must provide its immutable producer generation to =submit_raw(expected_generation=...)=. Pipeline ingress acquires the current capture permit, compares permit generation with producer generation before constructing a raw stage item, rejects mismatch with =StaleCaptureGeneration=, and scrubs all mutable raw buffers on rejection. Accepted items retain the producer generation exactly.
