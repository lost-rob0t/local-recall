Acceptance criteria copied into the working gate:
- no capture while off, paused, locked, denied, or faulted;
- raw capture flows directly into the in-memory redaction pipeline;
- multi-monitor and scaling fixtures are covered;
- backend failure cannot produce a plaintext screenshot artifact.

Additional issue requirements:
- full-desktop v0.1 capture with monitor geometry;
- optional focused-window crop only from validated metadata;
- memory-only pixel acquisition, no temporary files;
- preserve timestamp, dimensions, monitor geometry, and capture provenance;
- respect lifecycle/pre-capture authorization on every invocation;
- bounded capture duration and safe display-disconnect handling.

** Research ledger
*** Repository evidence
- The public capture port accepts only =ApprovedCaptureRequest= and returns =RawFrame=. The Xorg backend must remain downstream of the existing lifecycle/policy authorization rather than create a second policy state machine.
- =RawFrame= validates aware timestamps, positive dimensions, stride, pixel format, and exact byte length. Its current shape does not carry explicit monitor geometry or backend provenance, so issue #19 requires an additive project-owned capture provenance contract rather than smuggling geometry into arbitrary metadata.
- Pipeline ingress already destroys stale/cancelled raw work and preserves generation identity. Issue #19 should compose with that machinery and must not add a competing cancellation generation.

*** External evidence
- Xlib specifies =XGetImage= as the primitive for returning drawable pixels and notes that the returned =XImage= lives in client memory. It may return NULL and can raise drawable/match/value errors. Source: X.Org Xlib C Language X Interface, current release.
- X.Org's current concepts guide warns that core =GetImage= is slow and exposes framebuffer alignment/padding/byte ordering. That makes a thin, validated conversion boundary mandatory and argues against exposing native XImage layout to the rest of Local Recall.
- Historical X.Org security advisories include libX11/XGetImage validation defects. Treat the X server/native image structure as an untrusted boundary: bound dimensions and byte counts before copying, and use a maintained system libX11 rather than reimplementing the X wire protocol.

** Evidence-derived design
*** Chosen direction
Use a narrow Xlib adapter behind =CaptureBackend=, with native calls isolated in one module and an injectable reader seam for deterministic tests. Capture the root drawable for full-desktop v0.1. Obtain monitor geometry through an independently injected monitor-layout reader, normalize it into project-owned immutable types, then call Xlib for one bounded root-image acquisition. Convert the native image immediately to a canonical project pixel format before constructing =RawFrame=.

The production backend owns no persistence and no temporary-file path. It receives only an =ApprovedCaptureRequest=. Deadline checks happen immediately before entering the blocking native call and immediately after it returns; native work runs through a bounded executor boundary so cancellation/timeout cannot unblock later persistence merely because the native function eventually returns.

Focused-window capture uses one authorized virtual-root image followed by an in-memory crop from validated normalized geometry. It does not call =XGetImage= on the focused window itself, avoiding viewability/overlap/depth races at a second X11 read boundary.

*** Rejected alternatives
- Shelling out to ImageMagick/import, scrot, or xwd: stdout could be kept in memory, but this adds executable/version/parser variability and a larger hostile-output surface. It also makes provenance and pixel-format guarantees depend on external CLI behavior.
- Reimplementing X11 GetImage over the wire: unnecessary protocol/security complexity when the platform already provides maintained libX11.
- Letting the backend evaluate lifecycle, lock, or privacy state itself: duplicates #7/#17/#18 authorities and creates race-prone split-brain authorization.
- Writing screenshot files and reopening them: directly violates the issue's plaintext-artifact invariant.
- Capturing the focused window as a second X drawable: adds X11 visibility/overlap/depth failure modes without improving the privacy boundary; root capture plus validated memory crop is simpler and deterministic.

*** Invariants
1. The public production capture method requires a typed =ApprovedCaptureRequest=; no unauthenticated convenience method exists.
2. Generation on the returned frame equals the approved request generation exactly.
3. Backend/native errors expose fixed sanitized reason codes, never display strings, window titles, pixel bytes, native exception text, paths, or command lines.
4. No production capture module imports filesystem/tempfile/image-file encoders or opens a path for pixel persistence.
5. Native dimensions, stride, format, and byte counts are bounded and validated before copying into Python-owned bytes.
6. Monitor rectangles are bounded, normalized, associated with the same virtual-root coordinate space, and retained as typed provenance.
7. Focused-window cropping is optional and accepted only when geometry originates from already validated normalized metadata; otherwise full-desktop capture remains the safe behavior.
8. Timeout/cancellation/stale generation never converts a late native result into accepted downstream work.

*** State and ownership
- lifecycle generation: existing lifecycle authority;
- capture policy authorization/revision: existing policy authority;
- lock/idle safety: existing session-safety authority;
- X11 connection and native pixel acquisition: Xorg backend only;
- monitor-layout parsing/normalization: Xorg monitor reader only;
- persistence/redaction: existing downstream pipeline only.

*** Failure and race analysis
- display disconnect before/during capture -> fixed backend-unavailable/capture-failed result; no frame constructed;
- lock/privacy transition after authorization -> existing generation/policy invalidation makes returned work stale; backend must retain request generation and downstream gates re-check it;
- timeout while Xlib call is blocked -> caller sees bounded failure; eventual late native result is discarded and never submitted;
- malformed native image/overflow -> fail before copying;
- monitor topology changes between layout read and pixel read -> retain observed layout timestamp/revision and reject impossible geometry; later iteration may add a same-capture topology recheck if tests show this is necessary;
- focused-window geometry stale or outside root -> reject crop request and fail closed to full desktop rather than reading arbitrary coordinates.

*** Migration/configuration
No persistent-data migration is intended. Frame/provenance domain types may gain additive fields. No remote-provider or network configuration changes belong to this issue.

** Why Iteration 1 was superseded
Further adversarial research changed the native-acquisition decision. The issue does not require an in-process Xlib binding; it requires bounded, memory-only Xorg capture with no plaintext artifact. X.Org's =xwd= utility already provides the root-window dump on standard output by default, and the XWD wire/file header is a small specified structure whose integer header fields are stored MSB-first. Running a fixed =xwd -root -silent= child behind a hard process deadline gives a stronger kill boundary than a Python FFI call into a potentially blocked Xlib request.

The original rejection of =xwd= was therefore too broad. The relevant danger is uncontrolled shell/file/format behavior, not the mere fact that an executable is used. A fixed absolute executable, no shell, stdout-only capture, strict XWD parser, output cap, sanitized errors, and child termination on timeout/cancel satisfy the privacy and boundedness invariants more directly.

No Iteration 1 code was preserved merely to save sunk cost. The project-owned =ApprovedCaptureRequest=, generation, =RawFrame= provenance, trusted in-memory crop, and downstream policy/redaction boundaries remain valid because they are independent of native acquisition.

** External evidence that changed the design
- X.Org =xwd= documentation: output is standard output when no output file is given; =-root= selects the root window; =-silent= suppresses the bell. This allows a zero-tempfile capture path.
- XWD =XWDFile.h=: the fixed header is 25 CARD32 fields / 100 bytes, file version 7, with explicit pixmap format, dimensions, byte order, bits-per-pixel, bytes-per-line, visual class, RGB masks, color-table count, and window geometry. Header integer fields are MSB-first. The parser can therefore reject unsupported layouts before allocating/copying normalized pixels.
- =xrandr --listmonitors= provides monitor rectangles in the same X root coordinate space. Reading monitor layout before and after =xwd= allows topology changes during capture to fail closed rather than attaching stale geometry.

** Iteration 2 chosen design
1. =XorgCaptureBackend= remains the only public pixel-capture adapter and still requires =ApprovedCaptureRequest=.
2. =XwdSnapshotReader= reads monitor topology, obtains one root XWD byte stream, reads topology again, rejects changes, strictly validates/decodes the XWD stream, and emits canonical packed RGB8.
3. =FixedXwdNativeRunner= issues only two command identities: =xwd -root -silent= and =xrandr --listmonitors=. Callers cannot interpolate captured values into arguments.
4. =BoundedNativeCommandExecutor= is isolated from capture parsing. It maps fixed command IDs to absolute executable paths, supplies a minimal X11 environment, bounds stdout/stderr, derives timeout from the immutable monotonic request deadline, and kills the child on timeout, output overflow, cancellation, or broken pipe state.
5. No native stdout/stderr, executable path, DISPLAY value, XAUTHORITY value, pixels, or command output may appear in public errors/reprs.
6. Focused-window mode remains root capture followed by a trusted in-memory crop. It never selects a second arbitrary drawable.

** New failure/race analysis
- =xwd= exits non-zero or display disappears -> sanitized =display-unavailable=; no frame.
- XWD malformed, truncated, oversized, unsupported visual/pixmap format, invalid masks/stride/dimensions -> =capture-format-invalid= before =RawFrame=.
- monitor topology differs before/after root dump -> =display-changed=; no frame.
- deadline already expired -> fail before process creation.
- deadline expires while helper is active -> kill child, drain/cancel pipe tasks, fixed =capture-deadline-expired=.
- caller cancellation while helper is active -> kill child, clean pipe tasks, re-raise cancellation; no late result.
- stdout/stderr exceeds bound -> kill child and fixed =capture-output-too-large=; bytes never enter errors.
- hostile process environment such as =LD_PRELOAD= or proxy variables -> excluded from the helper environment; only the minimum X11/session values plus fixed C locale are retained.
