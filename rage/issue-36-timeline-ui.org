* Design decisions
- Loopback-only HTTP server (stdlib =http.server=) that must be explicitly
  started; binds =127.0.0.1= exclusively (constructor rejects anything else) on
  an ephemeral port. No dependency, no build step, no third-party asset.
- Per-session bearer token minted at =start()=; constant-time comparison; every
  =/api= route requires it. The HTML shell is served without a token (it is
  content-free) and every API route is authorized.
- The server maps routes onto the closed =CliCommand= set through
  =cli_service.execute_command= and the =DaemonClient= port — the same
  authenticated IPC path, deadlines, and sanitized responses as the CLI. No new
  daemon commands; the daemon remains the sole authority.
- Every response carries =Cache-Control: no-store= and =Pragma: no-cache=.
  Previews are decrypt-on-demand pass-through with zero retained payloads and
  no disk writes anywhere in the server.
- Destructive deletion without =confirm: true= performs no daemon call and
  returns the exact scope; with confirmation the daemon's canonical scope
  resolution and audit still run.
- Emergency stop is keyboard-accessible in the shell (=accesskey="s"= and an
  =Escape= keydown handler) and maps to the urgent =stop= command.
- Session close (user-initiated) and inactivity expiry both clear the token and
  stop the server; verified by tests asserting credential invalidation and
  subsequent 401/socket closure.
- Remote answering is gated per answer: local-only unless the user explicitly
  confirms remote processing for that single question; the request payload
  carries the confirmation rather than any persisted consent.
