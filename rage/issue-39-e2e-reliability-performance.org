* Acceptance criteria
- E2E tests use isolated synthetic desktops and never inspect the developer's real screen.
- Resource usage remains bounded during soak and failure tests.
- Stop/privacy mode halts new persistence within a defined measurable bound.
- A seeded assertion failure, process crash, timeout, teardown failure, and empty scenario selection each fail the canonical E2E command.
- Required scenarios contain no skipped or expected-failure state at release time.
- A release report records passed scenarios, exact failures, and known limitations without relabeling failures as passes.

* Design decisions
- No daemon binary exists yet, so the E2E layer drives the REAL component stack
  in-process over a deterministic synthetic desktop: synthetic capture backend +
  OCR provider (deterministic text per frame), the actual redaction policy,
  envelope cipher with an injectable keyring backend, SQLite encrypted storage,
  the encrypted semantic index, retrieval, cited answering, the lifecycle
  gate/actor (pykka), the audit recorder, and the #37 health subsystem with
  live ports. Scenario steps drive ticks synchronously; no unbounded background
  queues exist by construction.
- A deterministic scenario clock feeds capture timestamps, envelope
  =created_at= (via a Clock adapter into the encryption stage), retention age,
  and time-scoped question planning — no wall-clock dependence.
- The synthetic embedding model is intentionally topical-permissive (shared
  baseline component keeps cosine above the retrieval floor). Documented in
  =docs/e2e.md=; citation/time-window filtering and the real index cosine math
  remain genuine.
- Self-tests: =scripts/verify-e2e-failure-modes= injects one failing scenario at
  a time (assertion, crash, timeout, teardown, zero =-k= selection, piped
  output) and succeeds only when each fails non-zero. Wired into
  =./scripts/check= and the CI failure-propagation job.
- Performance budgets are scenario assertions (fail the command, not warnings):
  capture tick < 0.5 s, stop halt < 2 s, query < 2 s, < 16 KiB/record storage
  growth over the soak, index/storage agreement each 40 captures, retention
  sweep reclaims. CI-calibrated; reference-hardware (8B-class) budgets are
  release-gate items in =docs/e2e.md=.

* Verification mapping
- Synthetic desktops only: harness uses no real display, session, or
  credentials; policy/config tests forbid real values.
- Bounded soak: latency/byte budgets + record/index agreement + retention
  reclaim assertions in =test_soak_scenario.py=.
- Stop bound: gate reaches =off= within 2 s and persistence refuses afterwards
  (=CaptureGateClosed=).
- Failure injection: six E2E modes plus the pre-existing nine general modes all
  verified non-zero by dedicated scripts inside the canonical gate and CI.
- No skips/xfail: check-policy meta-tests from #38 scan every =tests/*.py=.
