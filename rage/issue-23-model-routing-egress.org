** External primary-source research
- OpenAI current API uses HTTPS bearer-authenticated API requests; adapter/protocol details must remain behind the provider port because the endpoint surface changes independently of routing/privacy semantics. Source: https://platform.openai.com/
- OpenRouter exposes OpenAI-compatible chat completions and documents provider/router fallback. Local Recall must not accept implicit upstream fallback as a substitute for explicit egress authorization. Sources: https://openrouter.ai/docs/quickstart and https://openrouter.ai/docs/guides/features/router-metadata
- Google Gemini exposes =models.generateContent= plus API-key authentication, while Google is evolving newer interaction surfaces. Provider protocol churn therefore stays behind project-owned adapters. Sources: https://ai.google.dev/api/generate-content and https://ai.google.dev/gemini-api/docs/api-key

** Evidence-derived design
1. Routing authority and egress authority are separate. A routing policy may select a remote candidate only when the request already carries explicit egress authorization; provider adapters cannot mint authorization.
2. =local-only= and =privacy-strict= are hard local-only modes.
3. =local-first= prefers a suitable local provider but does not convert local failure into remote permission. Local unavailability returns a sanitized failure.
4. =remote-explicit= is the only mode that may select remote. Selection requires explicit authorization, an exact authorized provider, capability/privacy compatibility, and authorized data classes.
5. Closed egress classes are =redacted-text=, =approved-metadata=, and =redacted-image=. Images require explicit image authorization.
6. =EgressAuthorization= is immutable control data: authorization ID, exact provider ID, allowed data classes, and maximum payload bytes. It contains no prompt/content.
7. =EgressPayload= is passed through =EgressGate= before any network adapter. The gate re-scans text/metadata, rejects sensitive metadata names, verifies every present modality is explicitly authorized, computes a canonical digest/byte count, and enforces the authorization byte ceiling.
8. Only =ApprovedEgressPayload= may cross into future remote-provider adapters; its content fields are excluded from repr/control metadata.
9. No adapter-level cross-provider fallback. Any retries must remain on the same authorized provider/endpoint, bounded by deadline/cancellation, and only for explicitly classified transient failures.
10. Credentials are resolved from a reference immediately at the transport boundary and never retained in config, repr, audit, errors, or response metadata.

** Rejected alternatives
- automatic local-first -> remote fallback: violates issue acceptance and TB-08;
- provider adapters deciding privacy eligibility: duplicates/bypasses central policy;
- =PrivacyClass= alone for modality authorization: cannot express image-denied-by-default cleanly;
- raw =GenerationRequest= directly into remote adapters: bypass risk around re-scan/preview/size validation;
- embedded API keys or arbitrary user-supplied auth headers: widens secret/log injection surface;
- OpenRouter implicit multi-provider fallback: one Local Recall authorization could reach an unapproved upstream provider;
- cross-provider retries: changes privacy route under an availability failure.

** Security/privacy invariants
- routing decisions contain no captured content;
- no remote decision without an explicit authorization ID;
- raw capture and secret material cannot be remotely routed;
- images require explicit image authorization;
- local provider failure never changes routing mode or authorization state;
- remote provider failure never triggers a different provider automatically;
- network adapters may receive only already-approved bounded payloads;
- seeded secrets and sensitive metadata must fail before transport;
- prompt/OCR/title/image bytes, credentials, headers, and provider bodies are absent from repr/audit/error control surfaces.

** Failure/race analysis
- local provider disappears after discovery -> sanitized local unavailable, no remote reconsideration;
- authorization revoked/changed before send -> transport consumes only a provider-bound =ApprovedEgressPayload= and cannot widen the selected provider/data classes;
- payload changes after preview -> immutable approved payload digest/byte count prevents silently widening the authorized content;
- secret re-scan fails/detects content -> no transport;
- redirect -> reject rather than follow to an unapproved origin;
- 429/5xx -> no route change; retries are same-provider and only for explicitly classified transport failures;
- cancellation/deadline expiry -> close/fail the same request and do not retry elsewhere;
- malformed/oversized provider response -> sanitized provider failure without body logging.

* Iteration 2 - provider protocol and transport boundary
** Implemented contracts
- Provider strategies now exist for =openai-compatible=, =openrouter=, =anthropic=, and =google= behind project-owned request builders.
- Remote provider configuration remains globally and individually disabled by default. Enabled providers require kind, HTTPS endpoint, model ID, and credential reference.
- OpenRouter request construction explicitly disables upstream provider fallback so one Local Recall authorization cannot silently fan out to another provider.
- Google model identity is bound into its configured =models/<model>:generateContent= request path rather than accepted from arbitrary request data.
- Credential resolution occurs immediately before request construction through the =os-keyring= provider seam. Credential values are repr-hidden, validated, and never returned in control results.
- The built-in transport opens a direct TLS connection with hostname/certificate verification, does not consume proxy routing, does not follow redirects, fixes method/transport-owned headers, rejects header injection, and bounds headers, request bytes, response bytes, and total request time.
- Responses must be HTTP/1.1 200 with one valid Content-Length. Transfer encoding, redirects, malformed/duplicate headers, truncation, oversized bodies, invalid JSON, TLS/connection errors, and timeouts map to fixed sanitized failures without response-body disclosure.
- The executor retries only explicitly classified transient transport failures, against the same already-authorized request/provider, under a bounded attempt count and total deadline. Cancellation propagates immediately.
- Provider builders currently accept approved redacted text only. Central egress can authorize metadata/images, but provider encoders deliberately reject those modalities until a specific reviewed wire encoding is implemented; this prevents a generic authorization from becoming an accidental image-upload capability.

** Verification coverage
- Mock/injected transport fixtures verify auth/header construction, provider request shapes, OpenRouter no-fallback behavior, redirect denial, response bounds, sanitized errors, timeout, cancellation, retry exhaustion, and same-provider execution.
- Routing tests prove =local-only= and =privacy-strict= cannot select remote, =local-first= never converts a local failure into remote permission, and provider errors do not select a less-private route.
- Egress tests prove exact provider/data-class binding, images denied unless explicit, deterministic secret re-scan, sensitive-metadata rejection, canonical byte limits/digest, and content-redacted representations.
- Credential tests use synthetic/injected backends and never contact a real keyring or provider.
