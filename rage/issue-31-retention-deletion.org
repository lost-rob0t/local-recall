- Dependencies: #10, #11, #30 (satisfied)

* Acceptance criteria
- Expired records are removed from every derived structure.
- Quota pressure cannot delete outside the configured policy silently.
- Interrupted garbage collection resumes safely.
- Purge-all leaves no decryptable capture records using the active key material.

* Research
*** Architecture evidence
- The catalog is deliberately content-free: day buckets, blob sizes, and opaque identifiers only. Age and size selection therefore need no decryption; application/workspace retention requires bounded decrypt-on-demand.
- Canonical storage already provides an idempotent crash-safe per-record delete and a recovery routine that completes interrupted deletions, repairs intents, and quarantines corruption.
- #30 established the surviving-record activity rebuild and the content-free deletion journal; the same canonical-deletion path is reused here instead of inventing a second eviction mechanism.
- KeyProvider supports rotation and destruction; envelopes carry per-record wrapped data keys, so removing an envelope removes the only wrapped copy of its data key.

*** Adversarial conclusions
1. Rejected: plaintext retention columns or scope predicates in the catalog (violates #11 leakage boundary).
2. Rejected: delete-blob-first eviction without the canonical state machine (orphans plaintext under crash).
3. Rejected: unbounded context scans (application/workspace rules decrypt only the disputed age window under a strict budget; overflow fails closed).
4. Rejected: applying retention from derived-state observers; only canonical catalog state drives selection.
5. Accepted: plan/execute split with dry-run plans, keyset-paged catalog walks (bounded pages), watermark eviction in canonical (day, record) order, idempotent derived-state reconciliation, and key destruction as the final purge step.

** Known scope decisions
- Record-type retention: the only existing artifact kind is =capture-record=; the age policy applies to it. Catalog =artifact_kind= is content-free, so future typed records can extend the rule set without schema leakage.
- Scheduling belongs to the daemon composition (#40); the engines are invocable and idempotent by design.
- Unbounded application-wide purges remain out of scope by design; purge-all is the explicit whole-store operation.
